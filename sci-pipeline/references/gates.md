# 게이트별 점검 항목

각 항목 끝 괄호는 출처다. 프로젝트 사고는 P-draw·P-twin·P-prior(`references/incidents.md` 범례), 공개 근거는 `references/sources.md`의 약칭.
audit 모드에서는 항목마다 PASS / FAIL / UNSET / 미확인 / N/A 와 근거 `파일:줄`을 적는다. UNSET = 아직 결정되지 않음(정할 사람이 있음), 미확인 = 결정은 있으나 실행·검증하지 못함(이유를 적는다).

---

## G1. 목표·추정량

- [ ] 1차 질문이 하나다. 확장 과제(신뢰도·종단·전이 등)는 1차 과제의 **대체가 아니라 다음 단계**로 적혀 있다. (P-draw, P-prior)
- [ ] 추정량(무엇의 어떤 차이를 어떤 단위로 평균하는가)과 **독립 단위**(사람·가족·기관)가 명시돼 있다. (P-twin, REFORMS)
- [ ] 기준선이 문헌상 강한 비LLM·인구통계 모형을 포함한다. 성과는 **기준선 대비 증분**으로만 보고한다. (P-draw, P-twin)
- [ ] 정확도처럼 유병률에 따라 무의미해지는 지표를 주성과로 쓰지 않는다. 작동점 지표(PPV·NPV)는 표본이 아니라 대상 현장 유병률로 환산한다. (P-draw, TRIPOD+AI)
- [ ] 서로 다른 정보원·모집단·라벨에서 나온 수치를 같은 축에 놓고 비교하지 않는다. (P-draw)
- [ ] 관찰자료의 조건 변경을 처치 효과로 해석하지 않는다. 인과 표현을 쓰면 인과 추정량과 식별 가정이 있다. (P-twin)
- [ ] 기준선에 예측 시점에 이미 있는 값싼 정보(같은 사람의 과거 측정·행동 이력)가 들어 있다. 인구통계만인 기준선으로는 "새 정보의 증분"을 주장할 수 없다. (P-twin, 신선 컨텍스트 설계 시험 2026-10-04)
- [ ] 핵심 목표(아이디어의 중심 의도)가 1차 질문으로 남아 있고 확장으로 강등되지 않았다. 범위 축소는 핵심 목표 안에서 했다. (신선 컨텍스트 설계 시험)
- [ ] 순차·생성 모델이면 joint(teacher forcing) / 주변분포 / 자유 생성 채점이 따로 정의돼 있고, 부분 관측 주변화와 중단(terminal) 처리가 정해져 있다. (P-twin)

## G2. 자료 계약 (halt)

- [ ] 스키마(열·형·허용값)가 문서와 **검증 코드** 둘 다에 있다.
- [ ] 식별자 정규화 규칙이 하나의 함수에만 있고, 쓰기·읽기가 같은 정규화를 쓴다. 앞뒤 공백·접두어·대소문자 변형이 검사된다. (P-draw)
- [ ] 범주 표기(대소문자·한/영 혼용)는 단일 정규화 함수에서 처리하고, **모르는 값은 halt**한다. (P-draw)
- [ ] 결측 부호와 라벨 결측이 명시적으로 거부된다. 결측을 정수로 캐스팅해 조용히 한 범주가 되는 경로가 없다(아키텍처마다 캐스팅 결과가 다를 수 있다). (P-draw)
- [ ] 시각은 timezone-aware이고 `측정 ≤ 이용 가능 ≤ 예측 시점`이 검사된다. (P-twin)
- [ ] 순서 키(시퀀스·획·시행 순서)가 실제 시간 순서와 일치하는지 검사하고, 어긋나면 재정렬하지 않고 halt한다. (P-draw)
- [ ] 검사가 실패를 찍고도 결과를 쓰거나 exit 0으로 끝나는 경로가 없다. (P-draw)
- [ ] 실자료가 없거나 일부 단계가 실패할 때 **합성·자리표시 자료로 대체하는 코드 경로가 없고**, 있다면 사람 승인과 명시 플래그가 필요하다. (SciIntegrity-Bench, P-draw)
- [ ] 원자료·식별자·개인별 파생자료가 Git 밖 승인 위치에 있고 `.gitignore`가 확장자 전반을 막는다. (P-twin, P-draw)

## G3. 분할·누수

- [ ] 분할 단위가 참가자(필요하면 가족·기관)이고 행·시행·세션 단위 분할이 없다. (세 프로젝트 공통, Varoquaux 2017, Rosenblatt 2024)
- [ ] 표준화·대치·특징 선택·하이퍼파라미터 튜닝·보정이 전부 fold 안에서 적합된다. 튜닝은 nested. (P-draw, Kapoor & Narayanan)
- [ ] 입력 allowlist가 있고 미래 정보·라벨에서 파생된 변수·동시점 진단이 막힌다. (P-twin, Kapoor & Narayanan)
- [ ] 분할 간 식별자·가족·시간 구간 중복을 **실행으로** 확인했다(`scripts/group_overlap_audit.py` — 스킬 디렉터리의 스크립트이며 대상 레포에 없어도 FAIL 사유가 아니다). 중복 없음은 독립성의 증명이 아니다.
- [ ] canary(심어 둔 표식)로 정답이 모델 입력·캐시·로그에 새는지 스캔한다. (P-prior)
- [ ] 생성·예측 함수가 미래 정답에 접근할 수 없다(인자·캐시·전역 상태). 미래 정답을 바꿔도 출력이 같아야 한다. (P-twin)
- [ ] 진단용 실패 run을 효과 비교의 대조군으로 재사용하지 않는다 — 비교 때 양쪽을 새로 돌린다. (P-prior)
- [ ] 외부 벤치마크·사전학습 자료에 평가 대상이 포함돼 있는지 확인했다. (P-draw)
- [ ] 측정 여부·빈도·간격이 결과나 위험도에 따라 정해지는 자료(위험 기반 추적, 선택적 검사)라면, 결측 패턴·방문 빈도·간격만으로 결과를 맞히는 지름길 대조가 있다. (신선 컨텍스트 설계 시험 — 코호트 논문상 추적 간격이 아밀로이드 상태별로 다름)

## G4. 봉인 확인 분할

- [ ] 확인 자료는 개발 API로 접근할 수 없다(접근 시 예외 또는 감사 이벤트). (P-twin, P-draw)
- [ ] `preregister()`(또는 카드 동결) 없이 `final_test()`가 실행되지 않는다. (P-draw)
- [ ] 봉인 상태가 사라졌을 때 조용히 재봉인하지 않는다. 봉인 집합 개수·digest를 대조한다. (P-draw)
- [ ] 봉인 참가자 식별자를 출력·로그·커밋하지 않는다. 저장소에는 해시만. (P-draw)
- [ ] 한 번 본 확인 자료는 burned로 기록한다. 확인 결과를 본 뒤의 수정은 새 확인 자료를 요구한다. (P-twin, lockbox-holdout, Hosseini 2020)
- [ ] 신규 참가자(2차 배치)가 봉인 로직을 우회해 개발군으로 들어가지 않는다 — 미지 id는 halt. (P-draw)

## G5. 동결 카드

- [ ] 바꾸는 요소가 정확히 하나이고, 대조군 목록(원 기준선 + 형식 대조 + 정보량 맞춘 대조)이 있다. (P-prior, conduct-dl-research §9)
- [ ] 결과 전 고정 항목: 주지표, 최소 관심 효과(δ), 불확실성 방법(군집 bootstrap 단위), 다중성, 결측 경로, 중단 규칙, seed 정책, 탐색 예산, 계산 상한. (P-twin, conduct-dl-research §5)
- [ ] 미정 값은 `UNSET`이고 각 필드에 `fixed_when`(어느 게이트에서 누가 고정)이 있다. **지어낸 수치가 없다.** 합성 fixture용 임계값이 실제 카드로 복사되지 않았다. (P-twin, P-prior)
- [ ] 카드가 sha256으로 동결돼 있고 run이 그 해시를 검증한다. 동결 뒤 변경 시도는 차단된다. (P-prior)
- [ ] 동결 해시가 run 디렉터리 밖의 고정점(git 커밋, 읽기 전용 위치)에도 있다. 같은 폴더의 장부·사이드카만으로 검증하면 장부를 지우거나 카드와 함께 고쳐 결과를 본 뒤 재동결할 수 있다. (pipeline-reviewer 시험)
- [ ] git 이력상 카드·프로토콜 커밋이 해당 결과 커밋보다 먼저다. (Orchestra autoresearch, Nosek 2018)

## G6. 합성 고정구 (시험용일 뿐)

- [ ] 심은 효과가 있는 경우와 효과 0인 경우가 둘 다 있다. (P-draw)
- [ ] 구조를 깨는 대조(순서 섞기·앞 맥락 지우기)가 있고 그때 성능이 떨어져야 통과한다. (P-draw)
- [ ] 손으로 계산한 정답이 있는 작은 fixture가 있다(예: joint 확률 열거, 사람 가중 평균). (P-twin)
- [ ] 정답 회수를 **한 점이 아니라 매개변수 범위**에서 확인한다. (Anthropic long-running Claude, Wilson & Collins 2019)
- [ ] 출력 확률·점수의 수학적 성질(합 1, 범위, NaN/Inf, 정규화 질량)을 조용히 clip하지 않고 검사한다. (P-twin)
- [ ] 리더보드·본 경로에 올라가는 **그 모형**이 고정구를 통과한다(대리 구현만 통과하는 상태가 아니다). (P-draw)
- [ ] 합성 결과의 효과크기·검정력·신뢰도를 실자료 전망으로 쓰지 않는다. 합성 산출물을 증거 폴더에 쓰지 않는다. (P-draw, P-prior)
- [ ] 실패한 고정구는 기준을 완화하지 않고 실패로 남아 있다. (P-draw)
- [ ] 손계산 정답은 닫힌식이나 허용오차보다 충분히 많은 자릿수(8자리 이상)로 적혀 있어, 올바른 구현이 반올림 상수 때문에 실패하지 않는다. (pipeline-reviewer 설계 시험)

## G7. 실행 기록·환경

- [ ] run마다 config·code(git SHA)·input·카드 해시와 환경(패키지 잠금, 하드웨어)이 기록된다. (P-prior, P-twin, DataLad/DVC)
- [ ] 실패한 seed·설정·인프라 실패도 장부에 남고 탐색 예산에 포함된다. 좋은 seed만 고르는 경로가 없다. (P-twin)
- [ ] 평가 코드·테스트·채점기 파일이 해시로 고정되고, 구현 작업이 이를 수정하면 FAIL이다. (METR reward hacking, MLE-bench)
- [ ] 같은 코드를 쓰는 **모든 실행 환경**(아키텍처·가속기·라이브러리 버전)에서 수치 동작(정밀도 지원, 캐스팅, 결정성)을 실행 전에 확인했다. (P-draw)
- [ ] 공유 자원(GPU 등) 경합에 의한 실패를 코드 결함·과학 결과와 구분해 기록한다. 기준을 낮추거나 skip하지 않는다. (P-draw)
- [ ] 외부 차단 요인(접근·인증·하드웨어)마다 상태·측정 시점·증거 파일이 있고, 조건이 바뀌지 않은 실패를 같은 방식으로 재시도하지 않는다. (P-prior)
- [ ] 재생성 산출물(결과 표 등)은 생성 스크립트와 같은 커밋에서 갱신되고, 텍스트 치환 후 새 문구 존재를 assert한다. (P-draw)

## G8. 판정 분류

- [ ] 판정 어휘가 keep / modify / stop / inconclusive / no_candidate로 고정돼 있다. (P-prior)
- [ ] 단계 상태(실행 성공/실패)와 연구 판정이 별개 필드다. 소프트웨어·인프라 실패가 과학적 null로 기록되지 않는다. (P-prior)
- [ ] 실패 유형을 구분한다: 구성 불가 / 측정 역량 부족 / 방향 반대 / 실용 효과 미달 / 정밀도·검정력 부족(→ inconclusive) / 누수·교란 / 실행 무결성. (conduct-dl-research negative-results)
- [ ] 무시할 만한 효과와 중요한 효과를 둘 다 포함하는 구간은 inconclusive다. 검정력 부족 null을 "효과 없음"으로 쓰지 않는다. (conduct-dl-research, Varoquaux 2018)
- [ ] 판정 방향(단측/양측)이 결과 전에 고정됐다. 양측 검정이 음의 차이를 '유의'로 찍는 경우를 성과로 쓰지 않는다. (P-draw)
- [ ] 비교 판정이 keep이 아니면 확인 자료를 열지 않는다. (P-prior)
- [ ] null·실패한 탐색도 장부와 보고에 남는다. (P-twin, P-prior)
- [ ] 판정표가 모든 경우를 덮는다(효과 구간 × 대조 결과의 모든 조합에 처음 걸리는 행이 있음). "방향 반대"(상한<0)가 "실용 효과 미달"과 별도 유형이고, "≈" 같은 비교 기준이 수치로 정의돼 있다. (pipeline-reviewer 설계 시험)

## G9. 상태 분리·주장

- [ ] 상태를 문서 / 합성 테스트 / 구현 / 실자료 효과 / 외부 재현 / 임상 효용으로 따로 보고한다. 문서 "Proceed"가 게이트 통과가 아니다. (P-twin)
- [ ] 문헌 수치에 PMID·DOI와 코호트·표본수·유병률이 붙어 있고, 검사 건수와 사람 수가 구분돼 있으며, 미확인은 `[확인 필요]`. 출처가 어긋나면 평균 내지 않고 충돌로 기록한다. (P-draw)
- [ ] "최초"·"세계 최고" 같은 선점 주장이 없다. 공백 주장은 무엇을 조사했고 무엇이 없었는지로 쓴다. (P-draw, P-prior Brain-JEPA 정정)
- [ ] 같은 정의(지표·사다리·모형 목록)가 문서와 코드에 따로 있으면 정본을 코드로 정하고, 문서는 코드에서 생성하거나 대조 검사가 있다. (P-draw)
- [ ] 모든 상태 문장에 측정 시점과 증거가 붙어 있고, 문서끼리 상태가 충돌하면 실측으로 해소한다. (P-twin, P-prior)
- [ ] 게이트 통과 기록의 작성자와 리뷰어가 다르다. 자기검토 / 독립 AI 리뷰 / 인간 전문가 검토가 구분된다. (P-twin)
- [ ] AI가 추정한 수치·사실이 PI 확인 전 ground truth로 쓰이지 않는다. (P-prior)
- [ ] "완료" 주장에 테스트 출력 원문이 붙어 있고, skip·xfail이 PASS로 집계되지 않는다. (P-prior, Anthropic "declare victory")
